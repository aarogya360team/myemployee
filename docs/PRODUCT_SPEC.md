# Product spec — Aurel

Locked positioning lives in `src/lib/usp/positioning.ts`. Do not invent parallel marketing copy.

## What the merchant hires

Rahul — AI Sales & Customer Service Employee.

Not a chatbot, not a WhatsApp bot, not automation nodes.

Journey: enquiry → discovery → recommendation → price/quote → order → payment → delivery → follow-up → repeat. Escalate when unsafe.

## Merchant language

Say: “Connect WhatsApp”, “Rahul is working”, “WhatsApp needs attention”.

Never say: WABA, Phone Number ID, access token, webhook, API, Meta App, provider.

## MVP (must work)

1. Sign up  
2. Create business (name, type, city, language)  
3. Hire Rahul  
4. Choose WhatsApp path (existing number / new number / not sure)  
5. Teach catalogue (or skip and add later)  
6. Rules + escalation contacts  
7. **DEMO / TEST** conversation (never a live customer send)  
8. Go live  
9. If WhatsApp is `REAL`, inbound customer message is handled by Rahul  
10. Money dashboard shows only real attributed orders  

## Out of first MVP (architecture exists or stubbed)

Priya / Amit / Neha as full employees, PDF ingestion, purchased new numbers, voice, ads, admin console, guaranteed ROI.
